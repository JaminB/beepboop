# tools/bench/synthetic: the CI smoke bench (M0 step 6)

Runs every stage benchmark end-to-end on x86 with clips generated by the local Piper voice,
so a pull request can break the bench harness and be caught without a Pi. **It makes no gate
claims**: the corpus is flagged `synthetic: true`, the result file is labelled
`synthetic / x86 / not a gate result`, and `--gates` is never passed (the CLI would refuse).

```bash
uv sync --all-packages                     # includes piper-phonemize (an audio dependency) for TTS
uv run python tools/bench/synthetic/run.py --small --duration 20
```

What it does:

1. `python -m beepboop_bench.models fetch` (about 225 MB, cached in `models/_cache/`).
2. Generates `tools/bench/corpus/synthetic/` (git-ignored) from `beepboop_bench.synthetic`:
   12 commands x 3 "speakers" (one voice at three speeds), wake clips for whichever wake model
   is installed (the pymicro-wakeword builtin until `hey_beepboop` is published), a few minutes
   of "radio" soak speech, one negative clip.
3. `beepboop bench` for speaker, stt, tts, wake, endpoint, llm (skipped: no `--llm-live`), and
   ram + thermal over a short concurrent realtime e2e (both samplers no-op on x86 and say so).
4. Writes `tools/bench/results/<date>-<host>-synthetic.json`.

What the synthetic numbers mean: only that the harness runs and the models load with the
configured thread caps. Speaker EER is meaningless (one voice), WER is poor (a low-quality voice
into a 20 M-parameter model), `distance_m` is nominal, and there is no HA, no DAC, no earcon.
The Pi numbers come from `tools/bench/record_fixture.py` + `beepboop bench all --gates`.

CI: the `bench-synthetic` job in `.github/workflows/ci.yml` runs this on `workflow_dispatch` and
nightly (not on every PR: model download plus the realtime e2e takes a few minutes), with
`models/` cached by the manifest's hash, and uploads the result JSON as an artifact.
